L2OALM.L2OALM — Module
L2OALM

Self-supervised primal-dual learning with an augmented Lagrangian (PDL, Park & Van Hentenryck, AAAI 2023, arXiv:2208.09046) as an L2OCore primal-dual method.

The core of the package is framework-agnostic array code: the primal loss (eq. (5) of the paper), the dual targets (eq. (6)), the dual loss (eq. (7)), the violation measure (eq. (8)) and the penalty rule (eq. (9)) are plain functions of batches of parameters, primal points and multipliers, written with broadcasts and reductions only so that they differentiate with array AD and run on GPU arrays. Package extensions add

  • L2OALMLuxExt (load Lux): the training loop of Algorithm 1 for two Lux.Training.TrainStates (L2OALM.train!, also reachable as L2OCore.train_proxy!);
  • L2OALMBatchNLPKernelsExt (load BatchNLPKernels): an evaluator for ExaModels problems that evaluates the batch with KernelAbstractions kernels (CPU or GPU).

Method

L2OALM.ALMMethod — Type
ALMMethod(; ρ_init = 1.0, ρmax = 1e4, α = 10.0, τ = 0.8, max_dual = 1e6,
          augmentation = PDLAugmentation(), bounds = NoBoundMap(),
          dual_norm_eps = 1e-8)

Self-supervised primal-dual learning (PDL) with an augmented Lagrangian, Park & Van Hentenryck (AAAI 2023), as an L2OCore.AbstractPrimalDualMethod. A primal proxy x̂(p) and a dual proxy λ̂(p) are trained alternately (Algorithm 1 of the paper; see train!):

  • primal phase: minimize primal_loss (eq. (5)) with λ̂ frozen;
  • dual phase: regress λ̂ onto dual_target (eq. (6)) with dual_loss (eq. (7));
  • penalty: update_penalty (eq. (9)) from the violation_measure (eq. (8)).

Hyper-parameters (paper notation):

  • ρ_init: initial penalty ρ;
  • ρmax: safeguard ρ_max; α > 1: penalty growth factor; τ ∈ (0, 1): required violation decrease;
  • max_dual: multipliers are clipped to [-max_dual, max_dual] (a numerical safeguard that is not in the paper);
  • augmentation: PDLAugmentation (paper) or PHRAugmentation;
  • bounds: NoBoundMap (variable bounds are rows with multipliers), SigmoidBoundMap or HardSigmoidBoundMap (bounds enforced by the output map and not dualized, as in the paper);
  • dual_norm_eps: smoothing of the norms of eq. (7) so the loss is differentiable when the prediction equals the target.

Supported problem classes are LinearConic (box rows only), ConvexQuadratic and SmoothNonlinear (see L2OCore.supports). Training needs an evaluator whose batch_objective and constraint_values are differentiable (MatrixEvaluator, or the BatchNLPKernels evaluator for nonlinear problems).

The completed multipliers always have the sign of the dual cone of their row (see dual_sign_violation); with a bound-enforcing map the variable bounds hold exactly. The remaining constraints are not enforced: PDL drives violations down during training, and on unseen instances they are measured with L2OCore.evaluate.

L2OALM.AbstractAugmentation — Type
AbstractAugmentation

How the multipliers and the penalty enter the primal loss. Built-in choices:

  • PDLAugmentation: eq. (5) of Park & Van Hentenryck (2023), λᵀ r(x) + ρ/2 ‖v(x)‖² with r the signed residual and v the violation;
  • PHRAugmentation: the classical Powell-Hestenes-Rockafellar augmented Lagrangian.

Extension point. Subtype AbstractAugmentation and add a method of augmentation_term(aug, form, C, Λ, ρ) returning the per-instance term (a 1 × B row or length-B vector); everything else (dual targets, penalty schedule, training loop) is shared.

source
L2OALM.PDLAugmentation — Type
PDLAugmentation()

Primal loss term of eq. (5) in Park & Van Hentenryck (2023), extended row-wise to box constraints l ≤ c ≤ u:

\[\sum_i \big( λ_i^+ (c_i - u_i) + λ_i^- (l_i - c_i) \big) + \frac{ρ}{2} \sum_i \big( \max(l_i - c_i, 0) + \max(c_i - u_i, 0) \big)^2 .\]

For an inequality g = c - u ≤ 0 this is μ g + ρ/2 max(g, 0)², for an equality h = c - b it is λ h + ρ/2 h², i.e. exactly eq. (5).

source
L2OALM.PHRAugmentation — Type
PHRAugmentation()

Powell-Hestenes-Rockafellar augmented Lagrangian term

\[\sum_i \Big( \frac{ρ}{2} \operatorname{dist}\big(c_i + λ_i/ρ, [l_i, u_i]\big)^2 - \frac{λ_i^2}{2ρ} \Big).\]

Its gradient with respect to c is the (unclipped) dual target of eq. (6), λ + ρ σ(x, λ), so the primal step "sees" the multiplier one ALM update ahead. This is the classical ALM of Rockafellar (1973) and the form behind the "analytical dual" variant of PDL discussed for AC-OPF.

source
L2OALM.AbstractBoundMap — Type
AbstractBoundMap

Map applied to the raw primal output of the proxy before evaluation (map_primal). Built-in: NoBoundMap (identity) and SigmoidBoundMap / HardSigmoidBoundMap (variable bounds hold by construction; see enforces_bounds).

Extension point. Subtype it and add a method of map_primal and, if the map always returns points inside the variable bounds, of enforces_bounds.

source
L2OALM.NoBoundMap — Type
NoBoundMap()

Identity: the primal block of the proxy output is the prediction.

source
L2OALM.SigmoidBoundMap — Type
SigmoidBoundMap()

Maps each raw output z into its variable's bounds: l + (u - l) σ(z) for two finite bounds, l + softplus(z) for a lower bound only, u - softplus(-z) for an upper bound only, z for a free variable (and the fixed value for a fixed variable), followed by a clamp to absorb rounding, so the variable bounds hold exactly. Unlike a clamp, the map has a non-zero gradient everywhere.

source
L2OALM.HardSigmoidBoundMap — Type
HardSigmoidBoundMap()

The output layer of the paper's AC-OPF experiments (Appendix C.2): for a variable with two finite bounds, the convex combination l + (u - l) hardσ(z) with hardσ(z) = clamp(z/6 + 1/2, 0, 1). Variables with at most one finite bound are mapped as in SigmoidBoundMap. The variable bounds hold exactly. The gradient is zero where hardσ saturates (|z| ≥ 3), which is why SigmoidBoundMap is the default bound-enforcing map.

source
L2OALM.enforces_bounds — Function
enforces_bounds(bounds::AbstractBoundMap) -> Bool

Whether map_primal with bounds always returns points inside the variable bounds. When it does, the variable-bound rows of the formulation get no multiplier (project_multipliers sets them to zero): as in the paper, the variable domain Y is then handled by the architecture and only g and h are dualized. Fallback: false.

Formulation and decomposition

L2OALM.ALMFormulation — Type
ALMFormulation(evaluator, lower, upper, xlower, xupper, equality; sense = 1, bound = 0)
ALMFormulation(pipe::L2OPipeline)

The problem as the augmented Lagrangian method sees it:

\[\min_x \; s \, f(x; p) \quad \text{s.t.} \quad l \le c(x; p) \le u,\]

where c(x; p) = L2OCore.constraint_values(evaluator, X, P) stacks every constraint row (variable bounds included), l = lower and u = upper may contain ±Inf, and s = sense is +1 for minimization and -1 for maximization. xlower/xupper are the variable bounds (used by bound maps), equality is 1 on rows with l == u and 0 elsewhere, and bound is 1 on rows that are variable bounds (c_i(x) = x_j) and 0 elsewhere (default: no bound rows). Bound rows get no multiplier when the bound map enforces the bounds (see enforces_bounds), as in the paper, where the variable domain Y is handled by the network architecture.

All vectors share one array type so that the formulation lives on the same device as the evaluator: CPU Vectors for JuMP problems, device vectors for an ExaModels/BatchNLPKernels evaluator built on a GPU backend.

Constructors:

  • ALMFormulation(pipe) for an L2OCore.L2OPipeline whose method is an ALMMethod: rows are L2OCore.dual_layout(pipe.problem), the evaluator is pipe.evaluator.
  • ALMFormulation(bm::BatchNLPKernels.BatchModel) (extension L2OALMBatchNLPKernelsExt): rows are the ExaModel constraints followed by the variables (as bound rows).

Extension point. Any L2OCore.AbstractEvaluator that implements batch_objective and constraint_values (differentiably, for training) can be used; build the formulation with the positional constructor.

Multiplier convention. Inside L2OALM a multiplier λᵢ of row i lives in the normal cone of [lᵢ, uᵢ] at cᵢ(x): λᵢ ≥ 0 pushes against the upper bound, λᵢ ≤ 0 against the lower bound, and the Lagrangian is s f(x) + λᵀ c(x) (up to constants). This is the paper's convention after writing g(x) = c(x) - u ≤ 0 (multiplier μ = λ ≥ 0) and h(x) = c(x) - b (multiplier λ). JuMP.dual returns -λ; see to_jump_duals.

L2OALM.project_multipliers — Function
project_multipliers(method::ALMMethod, form::ALMFormulation, Λ::AbstractMatrix)

Clip multipliers (L2OALM convention, see ALMFormulation) to the sign pattern of their row and to [-max_dual, max_dual]: rows without a finite upper bound get λᵢ ≤ 0, rows without a finite lower bound get λᵢ ≥ 0. When the bound map enforces the variable bounds (enforces_bounds), the multipliers of variable-bound rows are set to zero (the paper dualizes only g and h). This is the projection onto a closed convex subset of the dual cone, so it is idempotent.

source
L2OALM.to_jump_duals — Function
to_jump_duals(Λ)

Convert between the L2OALM multiplier convention (λ in the normal cone of the row's box, see ALMFormulation) and the JuMP.dual convention used by L2OCore.Prediction (y = -λ, for both minimization and maximization).

L2OALM.from_jump_duals — Function
from_jump_duals(Y)

Inverse of to_jump_duals: multipliers in the L2OALM convention from duals in the JuMP.dual convention (λ = -y).

Losses and penalty schedule

L2OALM.primal_loss — Function
primal_loss(method::ALMMethod, form::ALMFormulation, P, X, Λ; ρ) -> Real
primal_loss(pipe::L2OPipeline, P, X, Λ; ρ)

Primal loss of eq. (5), averaged over the batch:

\[\frac{1}{B} \sum_{k=1}^{B} \Big( s f(x_k; p_k) + A_ρ\big(c(x_k; p_k), λ_k\big) \Big),\]

where A_ρ is augmentation_term for method.augmentation, P the parameters (num_parameters × B), X the primal points (already mapped with map_primal) and Λ the multipliers of the frozen dual proxy (L2OALM convention). Λ is projected with project_multipliers first. Differentiable in X when the evaluator is.

source
L2OALM.augmentation_term — Function
augmentation_term(aug::AbstractAugmentation, form, C, Λ, ρ) -> 1 × B

Per-instance multiplier and penalty term of the primal loss for constraint values C (num_rows × B) and multipliers Λ (same shape, already projected with project_multipliers). See PDLAugmentation and PHRAugmentation.

source
L2OALM.dual_target — Function
dual_target(method::ALMMethod, form::ALMFormulation, P, X, Λ; ρ) -> num_rows × B
dual_target(pipe::L2OPipeline, P, X, Λ; ρ)

ALM multiplier update of eq. (6) for primal points X and the previous multipliers Λ (the frozen copy of the dual proxy), in box form:

\[λ^{k+1} = Π_M\big(λ^k + ρ \, σ(x, λ^k)\big), \qquad σ(x, λ) = c(x) - Π_{[l,u]}\big(c(x) + λ/ρ\big),\]

which is max(μ + ρ g, 0) for an inequality g ≤ 0 and λ + ρ h for an equality h = 0. Π_M is project_multipliers (sign pattern and max_dual).

source
L2OALM.dual_loss — Function
dual_loss(method::ALMMethod, form::ALMFormulation, Λ, target) -> Real
dual_loss(pipe::L2OPipeline, Λ, target)

Dual loss of eq. (7), averaged over the batch: the norm of the inequality part plus the norm of the equality part of Λ - target,

\[\frac{1}{B} \sum_k \Big( \|(λ_k - t_k)_{\mathcal G}\|_ε + \|(λ_k - t_k)_{\mathcal H}\|_ε \Big), \qquad \|v\|_ε = \sqrt{\|v\|_2^2 + ε^2} - ε,\]

with ε = method.dual_norm_eps (smoothing, not in the paper, so that the loss is differentiable when λ_k = t_k).

source
L2OALM.violation_measure — Function
violation_measure(method::ALMMethod, form::ALMFormulation, P, X, Λ; ρ) -> Real
violation_measure(pipe::L2OPipeline, P, X, Λ; ρ)

Violation measure of eq. (8) on a batch: max_k ‖σ(x_k, λ_k)‖_∞ with σ as in dual_target, i.e. max(‖h‖_∞, ‖max(g, -μ/ρ)‖_∞). The paper takes the maximum over the whole training set; take the maximum of the batch values. It is zero exactly when x is feasible and complementary with λ.

source
L2OALM.update_penalty — Function
update_penalty(method::ALMMethod, ρ, v, v_prev) -> ρ_new

Penalty rule of eq. (9): min(α ρ, ρmax) if v > τ v_prev, else ρ. Use v_prev = Inf at the first outer iteration (the rule applies for k > 1).

The penalty never decreases and never exceeds the safeguard: ρ ≤ ρ_new ≤ max(ρ, ρmax).

Training

L2OALM.ALMTrainer — Type
ALMTrainer(primal, dual; ρ = 1.0)

Mutable training state of PDL (Algorithm 1 of Park & Van Hentenryck, 2023):

  • primal, dual: framework-specific states of the primal proxy (outputs num_decision_variables rows) and of the dual proxy (outputs num_rows multipliers, L2OALM convention); with the Lux extension these are Lux.Training.TrainStates;
  • ρ: current penalty; v_prev: violation measure of the previous outer iteration (Inf before the first one); iteration: completed outer iterations;
  • history: one NamedTuple per outer iteration with fields iteration, ρ (penalty used in that iteration), violation (eq. (8)), primal_loss and dual_loss (means over the last epoch of each phase).

Initialize the last layer of the dual proxy at zero so that the first primal phase minimizes the plain penalty loss, as in the paper.

source
L2OALM.train! — Function
train!(trainer::ALMTrainer, method::ALMMethod, form::ALMFormulation, inputs; kwargs...)
train!(trainer::ALMTrainer, pipe::L2OPipeline, inputs; kwargs...)

Run outer iterations of PDL (Algorithm 1) on the parameter matrix inputs (num_parameters × N, or an L2OCore.L2ODataset), updating trainer in place. Each outer iteration k:

  1. primal phase: primal_epochs epochs minimizing primal_loss (eq. (5)) with the dual proxy frozen;
  2. computes v_k with violation_measure (eq. (8)) over inputs;
  3. freezes a copy of the dual proxy (λ_k);
  4. dual phase: dual_epochs epochs minimizing dual_loss (eq. (7)) towards dual_target (eq. (6)) with the primal proxy and λ_k frozen;
  5. updates ρ with update_penalty (eq. (9)).

Methods are provided by extensions: load Lux for Lux.Training.TrainState proxies (keywords outer_iterations, primal_epochs, dual_epochs, batchsize, rng, ad, callback; see the package guide).

train! is not exported, because the name would clash with Flux.train!; call it as L2OALM.train!, or through the generic L2OCore.train_proxy!(pipe.method, pipe, trainer, inputs; kwargs...).

source
L2OALM.dual_sign_violation — Function
dual_sign_violation(problem::ParametricProblem, prediction) -> Vector
dual_sign_violation(form::ALMFormulation, prediction) -> Vector

Per instance, the largest violation of the sign conditions of the dual cone by the multipliers of prediction (an L2OCore.Prediction with a dual block, or a num_duals × B matrix / length-num_duals vector), in the JuMP.dual convention: y ≥ 0 for GreaterThan/Nonnegatives rows, y ≤ 0 for LessThan/Nonpositives rows, any sign for equalities and two-sided intervals.

ALMMethod makes this zero by construction (project_multipliers in L2OCore.complete). Sign feasibility alone does not make the multipliers dual feasible: PDL multipliers do not satisfy Lagrangian stationarity, so they need not give a valid bound through L2OCore.dual_bound.

L2OCore.complete — Method
L2OCore.complete(method::ALMMethod, pipe, inputs, output) -> Prediction

Split the stacked output [x; λ] (num_decision_variables + num_duals rows), apply map_primal to the primal block and project_multipliers to the dual block, and return the duals in the JuMP.dual sign convention.

L2OCore.loss — Method
L2OCore.loss(method::ALMMethod, pipe, inputs, output; ρ = method.ρ_init,
             multipliers = nothing, kwargs...)

The primal-phase loss (eq. (5)) of a stacked raw output [x; λ]: the primal block goes through map_primal; the multipliers are multipliers (L2OALM convention) when given, else the dual block of output with its derivative ignored, since the dual proxy is frozen in the primal phase. The dual phase uses dual_loss and dual_target; the full alternating scheme is train!.

L2OALMBatchNLPKernelsExt.BatchModelEvaluator — Type
BatchModelEvaluator(bm::BatchModel)
